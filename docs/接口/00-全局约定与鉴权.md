# 00 全局约定与鉴权

> 本文件是所有接口的公共合同。业务规则真源是《产品设计文档》;持久化结构真源是《数据库字段字典》;接口合同真源是本目录各模块文档。

## 1. 基础协议

| 项 | 约定 |
|---|---|
| 前缀 | C 端 `/app-api/**`;管理端 `/admin-api/**` |
| 认证 Header | `Authorization: Bearer {token}` |
| 响应外壳 | `CommonResult<T>`:`code`(0 成功)/`message`/`data`;分页 `PageParam{pageNo,pageSize}` → `PageResult<T>` |
| 错误码 | 复用 yudao `GlobalErrorCodeConstants`;业务错误码在业务模块 `ErrorCodeConstants` 注册 |
| 编码 | UTF-8;JSON `application/json`;上传 `multipart/form-data` |
| 时间 | 时间戳(毫秒,yudao 默认) |
| 字段命名 | API lowerCamelCase;数据库 snake_case |

## 2. 鉴权体系(二开,不自研)

**决策:在 yudao 原有鉴权体系上二次开发,不重新设计鉴权。**

| 端 | 方案 |
|---|---|
| 管理后台 admin-api | yudao OAuth2 密码模式 + RBAC + `TokenAuthenticationFilter` **原样复用,零改动**;客服账号 = system_users + 角色/菜单权限 |
| 小程序 app-api | member 模块已裁剪(登录接口缺失),**自建微信登录入口,复用 token 基础设施** |

**C 端二开方案:**

```
自建(仅登录入口): POST /app-api/auth/wechat-login
  wx.login code → code2session 换 openid → 查/建 t_user
  → 调 yudao OAuth2TokenService 签发 access_token + refresh_token
  → 落 system_oauth2_access_token(user_type = MEMBER)

复用(全部现成): TokenAuthenticationFilter 拦截 /app-api/**
               token 校验 / Redis 会话 / 刷新 / 登出 / 多端踢下线
               登录日志与审计链路、permit-all 白名单配置
```

**分层原则(强制):框架鉴权与业务权限分离**

| 类型 | 归属 | 例子 |
|---|---|---|
| 框架鉴权 | yudao | 是否登录、token 有效性、客服后台菜单权限(RBAC) |
| 业务权限 | **service 层校验** | cert_status=2 才能看需求广场、blacklist 禁投递、订单仅当事人可读、禁止自我成交、发布权 publish_enabled |

业务权限**不得**做成 RBAC 角色/注解,一律写在对应 service 方法入口(与《开发规范》"状态流转收口 service"一致),保证业务逻辑独立可剥离。

## 3. 接口安全矩阵(强制)

| 规则 | 说明 |
|---|---|
| 完整手机号 | **仅** `/admin-api/user/{id}`、`/admin-api/order/{id}` 有权解密;C 端一律掩码 `138****1234`;VO 层强制 |
| 详细地址/坐标 | 仅管理端需求接口可见;C 端详情/列表不返回字段(而非返回后前端隐藏) |
| 需求广场权限 | cert_status=2 且 blacklist=false(服务端校验,不信前端) |
| 投递申请校验 | 认证、非黑名单、需求可申请、**parent_user_id ≠ 自己**、无存量活跃申请 |
| 状态机收口 | 订单/申请/需求所有状态流转必须走对应 Service 的专用方法,禁止 Controller/其他模块散落 update |
| 身份不连坐 | blacklist 只拦老师端能力;封禁(status=1)拦全部 |
| 敏感词 | 简历/需求/评价文本提交时过敏感词库(内置词库+人工兜底) |
