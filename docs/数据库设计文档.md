## 1. 设计原则

| 原则 | 说明 |
|---|---|
| 手机号加密 | 所有落库手机号 AES 加密存储,密钥在服务器环境变量;**另存统一盐 SHA-256 哈希列 mobile_hash**(盐在环境变量),仅客服后台按手机号等值查找,不可逆 |
| 评价/履约跟人走 | 评价挂 `user_id`,反悔计数挂 `tutor_profile`,不挂简历/需求 |
| 联系方式唯一落点 | 完整手机号仅在 t_user,订单不复制手机号,后端按 user_id 现查现解密,仅后台接口有权调用 |
| 多值字段用 JSONB | 擅长科目、可授课区域、可授课时间等用 **JSONB** 列,配 **GIN 索引**,查询用 `@>` 操作符 |
| 状态字段用 SMALLINT | 状态/枚举一律 SMALLINT(不用 PG ENUM,演进时改类型麻烦);纯二值用 BOOLEAN |
| 向量一步到位 | t_tutor_resume 预建 `embedding vector(1024)` 列 + HNSW 索引,**先建列不填充**;数据积累后批跑 embedding 回填,语义检索即可启用 |
| 订单不做快照 | 订单只存关联 id(简历变更实时反映),二期量大再考虑快照 |
| 软状态优先 | 用户/简历/需求用状态字段控制,不物理删除(审核追溯需要) |
| 可见性与编辑解耦 | `visible`/`status` 只是"别人能否看到/申请"的开关,不参与内容编辑;编辑敏感字段 → 审核 → 通过才恢复可见 |
| 身份并存 | 三种身份(游客/老师/家长)由 profile 表存在性与状态推断,老师身份=cert_status=2,家长身份=publish_enabled=true,可同时拥有 |
| 处罚不连坐 | 身份级处罚只作用对应身份(blacklist 罚老师不影响家长身份);仅用户级封禁(status=1)两端全封 |
| 禁止自我成交 | 同一用户的家长身份需求,其老师身份不可投递(接口层校验);防自导自演刷单 |

## 2. ER 关系概览

```
t_user (1) ──(0..1)── t_tutor_profile (1) ──(1)── t_tutor_resume
   │                                 │                  │ (embedding 向量列)
   │──(0..1)── t_parent_profile      │──(0..n)── t_break_promise_log
   │                                 │
   │                                 可投递 ↓
t_demand (1) ──(0..n)── t_application (1) ──选中后──(1..0)── t_order (1) ──(0..2)── t_evaluation
   ↑(parent_user_id)          ↑(tutor_user_id)                        (from/to user_id,挂人)
```

- 家长发需求 → 老师投申请 → 家长选中 → 生成订单 → 试课 → 评价
- 评价从订单出发,但落点是"人"(from_user_id/to_user_id)

### 3.3 t_tutor_resume 简历表(一人一行,持续更新)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT IDENTITY PK | |
| user_id | BIGINT UNIQUE NOT NULL | 一人一简历 |
| name | VARCHAR(32) NOT NULL | 姓名 |
| avatar_url | VARCHAR(512) NULL | 头像(**选填**,微信头像能力 chooseAvatar 实现) |
| gender | SMALLINT NOT NULL | 1 男 / 2 女 |
| school | VARCHAR(64) NOT NULL | 学校(敏感字段) |
| education | VARCHAR(32) NOT NULL | 学历枚举(专科/本科/985/211/硕士,见 §4) |
| subjects | JSONB NOT NULL | 擅长学科数组,如 `["数学","物理"]`(敏感字段) |
| teach_grades | JSONB NOT NULL | 可授课年级数组(枚举见 §4) |
| experience | TEXT NULL | 家教经验(非敏感) |
| teach_time | JSONB NULL | 可授课时间,如 `[{"day":"周末","slots":["上午","下午"]}]` |
| teach_areas | JSONB NOT NULL | 可授课区域数组,如 `["海淀区","朝阳区"]` |
| hourly_min | DECIMAL(6,1) NULL | 期望时薪下限 |
| hourly_max | DECIMAL(6,1) NULL | 期望时薪上限 |
| intro | TEXT NULL | 个人介绍(非敏感,人工审微信号) |
| **embedding** | **vector(1024) NULL** | **语义向量(先建列不填充)**。由 intro+subjects+experience 等文本经 embedding API 生成,批任务回填;启用语义检索时建 HNSW 索引 |
| visible | BOOLEAN DEFAULT false | **可见性开关**(手动):仅控制他人能否看到/申请,**不涉及内容编辑**;审核中/被拒/强制下线时系统强制隐藏 |
| review_status | SMALLINT DEFAULT 0 | 0 待审核 / 1 通过 / 2 拒绝(敏感字段变更 → 回 0,且强制 visible=false) |
| review_reason | VARCHAR(255) NULL | 审核意见 |
| created_at / updated_at | TIMESTAMP | |

> **禁止字段**:简历任何位置无微信号字段;个人介绍中出现的微信号由客服审核时删除。
> **编辑重审规则**:修改敏感字段(school、education、subjects)→ review_status 回 0 且强制隐藏 → 审核通过自动恢复可见;修改非敏感字段不重审(走敏感词检测),可见性不受影响。
> **实际可见 = visible AND review_status=1 AND profile.blacklist=false**;隐藏期间存量申请在家长端查询时排除,已生成订单不受影响。

### 3.5 t_demand 需求表(家长可发多个)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT IDENTITY PK | |
| parent_user_id | BIGINT NOT NULL | 发布家长 |
| subjects | JSONB NOT NULL | 授课科目数组(敏感字段) |
| grade | VARCHAR(32) NOT NULL | 学段枚举(见 §4,敏感字段) |
| hourly_min / hourly_max | DECIMAL(6,1) NULL | 期望时薪区间(敏感字段) |
| tutor_gender_req | SMALLINT DEFAULT 0 | 0 不限 / 1 男 / 2 女 |
| tutor_edu_req | VARCHAR(32) NULL | 学历要求枚举(可空=不限) |
| city | VARCHAR(32) NOT NULL | 城市(敏感字段) |
| district | VARCHAR(32) NOT NULL | 区(前台展示仅到区) |
| address_detail | VARCHAR(255) NOT NULL | 详细地址到小区/街道(**前台脱敏不展示**,敏感字段) |
| address_lat / address_lng | DECIMAL(10,6) NULL | 地址 geocoder 转坐标(**前台不可见**,仅距离计算用) |
| teach_time_req | JSONB NULL | 授课时间要求 |
| student_info | TEXT NULL | 学生情况(非敏感) |
| remark | TEXT NULL | 备注/其他要求(非敏感,自由文本) |
| status | SMALLINT DEFAULT 0 | 0 接收申请中(可见可申请)/ 1 已选定老师 / 2 已关闭(完成/失败/超时/家长手动下架/举报核实强制下架/家长放弃)。**家长可重开:2→0**(有申请时弹确认),原申请记录保留;状态 1 不可手动下架 |
| review_status | SMALLINT DEFAULT 0 | 0 待审核 / 1 通过 / 2 拒绝(敏感字段变更 → 回 0,且强制不可见) |
| review_reason | VARCHAR(255) NULL | 审核意见 |
| edit_version | INT DEFAULT 0 | 编辑版本号,每次保存内容 +1;重开时对比快照值判定"编辑过" |
| expire_at | TIMESTAMP NULL | 超时下架时间(一周无人接单 → 后台提醒管理员,持续无人接自动下架) |
| closed_reason | VARCHAR(64) NULL | 关闭原因(已完成/试课失败/超时/家长手动下架/举报核实/家长放弃) |
| created_at / updated_at | TIMESTAMP | |

> 状态回退规则:试课失败 → 家长还要老师则 status 回 0(接收申请中);家长不要了则保持 2(closed_reason=试课失败)。已选定(status=1)期间不接受新申请。
> **编辑与可见性规则**:可见性仅控制"别人能否看到/申请";内容随时可编辑(2 状态下编辑)。敏感字段(科目/年级/地址/时薪)编辑 → review_status 回 0 且强制不可见 → 审核通过恢复;非敏感字段编辑走敏感词检测不重审。
> **重开规则**:status 2→0 时对比 edit_version 快照:编辑过 → 原申请置 5 已失效;未编辑 → 原申请保留。

### 3.6 t_application 申请表(老师投递记录)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT IDENTITY PK | |
| demand_id | BIGINT NOT NULL | 目标需求 |
| tutor_user_id | BIGINT NOT NULL | 投递老师 |
| status | SMALLINT DEFAULT 0 | 0 申请中 / 1 被选中 / 2 已撤回 / 3 已排除(反悔) / 4 已试课未通过(可再选) / **5 已失效(需求编辑后重开,清空)** |
| apply_at | TIMESTAMP | 投递时间 |
| updated_at | TIMESTAMP | |

- **唯一性**:部分唯一索引 `(demand_id, tutor_user_id) WHERE status IN (0,1,2,3,4)` —— 同一老师对同一需求仅一行申请
- 撤回(家长未选前):status 2,**终态不可重投该需求**(防重复+让老师三思)
- 家长选中:status 1,同时生成订单
- 老师反悔:status 3(排除该老师,家长不可再选他;需求回退 0)
- 试课失败:该老师 status 4(家长可再选),同行走状态流转(4→1),不产生新行;需求回退 0 或关闭(看家长意愿),其余申请保持 0 可继续参与
- 需求编辑后重开:该需求全部申请(状态 0 或 4 的)置 **5 已失效**,老师端列表可见"已失效";失效行不占唯一索引位,**允许老师重新投递(新行)**
- **简历隐藏(展示层规则,状态不变)**:老师简历隐藏期间,其 status=0 的申请在家长端申请列表**查询时排除**(不可见不可选);简历恢复可见后恢复显示。已生成订单不受影响

### 3.7 t_order 订单表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT IDENTITY PK | |
| demand_id | BIGINT NOT NULL | |
| application_id | BIGINT NOT NULL | 来源申请 |
| parent_user_id | BIGINT NOT NULL | |
| tutor_user_id | BIGINT NOT NULL | |
| status | SMALLINT DEFAULT 0 | 0 待确认 / 1 待收费 / 2 试课中 / 3 已完成 / 4 试课失败 / 5 已取消 |
| fee_status | SMALLINT DEFAULT 0 | **0 未收 / 1 已收 / 2 已退**(信息费,线下客服微信收取) |
| fee_collected_at | TIMESTAMP NULL | 收费时间(→试课中) |
| fee_refunded_at | TIMESTAMP NULL | 退费时间(试课失败 / 收费后取消) |
| fail_blame | SMALLINT NULL | **失败责任方:1 老师问题 / 2 家长问题**(客服与家长沟通后填写,审计追溯) |
| fail_reason | VARCHAR(255) NULL | 试课失败原因(客服填) |
| cancel_reason | VARCHAR(255) NULL | 取消原因(老师反悔 / 家长放弃,客服填) |
| created_at | TIMESTAMP | 订单生成时间(家长选中) |
| tutor_confirmed_at | TIMESTAMP NULL | 老师确认时间(→待收费) |
| finished_at | TIMESTAMP NULL | 客服标记完成时间 |
| updated_at | TIMESTAMP | |

> **状态机(信息费前置)**:
> ```
> 0 待确认 ──老师确认──→ 1 待收费 ──客服收费──→ 2 试课中 ──客服标记──→ 3 已完成
>    │(双方加客服微信)      (发放双方联系方式)              └──客服标记──→ 4 试课失败(退费)
>    │
>    ├─老师反悔──→ 5 已取消(需求回退 0,application 置 3 排除该老师)
>    └─家长放弃(管理端取消,收费前)──→ 5 已取消(需求关闭 2)
> 1 待收费 ──家长放弃(管理端取消,退费)──→ 5 已取消(fee_status=2,需求关闭 2)
> ```
> - 收费后取消/试课失败必须退费:**状态 4 或(收费后的)5 强制 fee_status=2**
> - 试课失败后续:家长还要老师 → 需求回退 0(可重新选老师);家长不要了 → 需求关闭 2(closed_reason=试课失败)
> - **管理端订单修改权限**:客服可取消订单(家长放弃场景)、标记完成/失败;失败必须填 fail_blame(1 老师 / 2 家长)+ fail_reason,留痕 t_audit_log(target_type=order)
> - 超时催办:状态 0 超 12 小时未确认 → 每日 8:00 定时任务提醒管理员催办,不自动取消

## 7. 关键场景查询说明

### 7.1 动态墙(脱敏投影,无新表)

```sql
SELECT d.district, d.grade, d.subjects, o.status, o.updated_at
FROM t_order o
JOIN t_demand d ON d.id = o.demand_id
WHERE o.status IN (2, 3)          -- 试课中 / 已完成
ORDER BY o.updated_at DESC
LIMIT 20;
-- 投影禁区:时薪、地址详情、经纬度、任何 user_id 相关字段
```

### 7.2 简历广场默认排序(评价+履约+活跃)

```sql
SELECT r.*,
       (SELECT ROUND(AVG(e.stars), 1) FROM t_evaluation e
        WHERE e.to_user_id = r.user_id AND e.direction = 1 AND e.status = 1) AS avg_stars
FROM t_tutor_resume r
JOIN t_tutor_profile p ON p.user_id = r.user_id
WHERE r.visible = true AND r.review_status = 1 AND p.blacklist = false AND p.cert_status = 2
ORDER BY avg_stars DESC NULLS LAST, p.report_count ASC, p.break_promise_count ASC, r.updated_at DESC;
```

### 7.3 按科目/区域筛选(JSONB @>)

```sql
-- 找"擅长数学且可授课海淀区"的可见简历
SELECT * FROM t_tutor_resume
WHERE visible = true AND review_status = 1
  AND subjects @> '["数学"]'::jsonb
  AND teach_areas @> '["海淀区"]'::jsonb;
```

### 7.4 距离筛选(Haversine,城市/区前置过滤 + 精算)

```sql
-- 老师当前位置 (lng, lat) = (:lng, :lat),按距离排序
SELECT id,
       6371000 * 2 * ASIN(SQRT(
         POWER(SIN(RADIANS((:lat - address_lat) / 2)), 2) +
         COS(RADIANS(address_lat)) * COS(RADIANS(:lat)) *
         POWER(SIN(RADIANS((:lng - address_lng) / 2)), 2)
       )) AS distance_meters
FROM t_demand
WHERE status = 0 AND city = :city          -- 城市前置过滤,砍掉绝大多数数据
ORDER BY distance_meters
LIMIT 50;
-- 可选优化:安装 earthdistance + cube 扩展,用 <@> 操作符更简洁
```

### 7.5 语义检索(pgvector,未来启用)

```sql
-- 家长需求描述向量化后 (:query = embedding API 输出)
SELECT r.id, r.name, r.school,
       1 - (r.embedding <=> :query) AS similarity   -- 余弦相似度(向量需归一化)
FROM t_tutor_resume r
JOIN t_tutor_profile p ON p.user_id = r.user_id
WHERE r.visible = true AND r.review_status = 1 AND p.blacklist = false
ORDER BY r.embedding <=> :query
LIMIT 20;
-- 混合查询(语义 + 业务过滤)一条 SQL:
--   AND subjects @> '["数学"]'::jsonb AND teach_areas @> '["海淀区"]'::jsonb
```

### 7.6 完整手机号访问控制(防跳单生命线)

- 手机号解密仅存在于**后台接口**(客服工作台),C 端接口一律输出 `138****1234` 掩码
- 代码层:加密工具类 `MobileCrypto` + 脱敏工具类 `MobileMasker`,C 端 VO 层强制掩码
- 客服按手机号查找:`SHA-256(手机号 + 统一盐)` 后等值查询 mobile_hash 列;盐在环境变量,不落库
