## 2. 后端代码规范

### 2.1 分层(强制)

```
controller(参数校验/鉴权/装配 VO,无业务逻辑)
  → service(业务逻辑/状态机/事务,唯一允许改状态的入口)
    → dal(mapper + dataobject)
```

- 状态流转一律走 service 层专用方法(如 `OrderService.confirm(id)`),禁止在任何地方裸 `updateById` 改状态
- 跨表一致性操作用 `@Transactional`(选中老师生成订单、反悔回退、收费登记)
- 禁止 Controller 直接调 Mapper

### 2.2 命名与工具

- 包:`cn.iocoder.yudao.module.tutor.{controller,service,dal,convert}`
- DO 命名 `XxxDO`(对应 t_ 表)、请求 `XxxSaveReqVO/XxxPageReqVO`、响应 `XxxRespVO`
- 时间字段 autoFill(created_at/updated_at),实体配 yudao `DefaultDBFieldHandler`
- 枚举常量统一放 `XxxStatusEnum`(SMALLINT 值 + 中文说明),禁止魔法数字

### 2.3 手机号加解密(安全红线)

- 统一工具类 `MobileCrypto`(AES,密钥环境变量)与 `MobileMasker`(掩码)
- **C 端 VO 禁止暴露 mobile 明文字段**:RespVO 只含 `mobileMasked`(如 `138****1234`);完整手机号仅管理端 VO
- 手机号哈希 `MobileHash.sha256(mobile)`(统一盐,环境变量),仅客服查找用

## 3. 数据库开发规范

| 规则 | 说明 |
|---|---|
| 状态/枚举 | SMALLINT + 枚举类,不用 PG ENUM 类型 |
| 多值字段 | JSONB + GIN 索引,查询用 `@>` |
| 布尔 | BOOLEAN(visible、blacklist、publish_enabled 等) |
| 软状态 | 业务表一律不物理删除,用状态字段 |
| 手机号 | 落库必加密;**任何表不得再存明文手机号/微信号副本**(订单不复制联系方式) |
| 索引 | 新增查询按 §字段字典 13 节清单;JSONB 加 GIN;不允许无索引的大表模糊查询 |
| 变更流程 | schema 变更:先改 `sql/01-schema.sql` → 本地重建验证 → 同步《数据库字段字典》→ 提交 |

## 4. 接口规范

- 路径:`/app-api/**`(C 端)、`/admin-api/**`(管理端),RESTful 动词 + 名词
- 响应:`CommonResult<T>`,分页 `PageParam/PageResult`;失败码复用 yudao 全局错误码,业务码在 `ErrorCodeConstants` 注册
- 入参校验:`javax.validation` 注解;手机号格式、枚举范围、必填项
- **权限在服务端校验,不信任前端**:需求广场认证校验、投递资格校验、订单当事人校验
- 所有接口遵循《接口/00-全局约定与鉴权》§3 安全矩阵

## 5. 业务规则速查(实现时必须遵守)

1. **防跳单生命线**:小程序端任何接口不返回完整手机号/详细地址/坐标;联系方式仅客服后台可见、线下发放
2. **订单状态机**:0 待确认 →(老师确认)→ 1 待收费 →(客服收费+发联系方式)→ 2 试课中 →(客服标记)→ 3 完成 / 4 失败(先退费);取消分支见字段字典 §13
3. **信息费**:99 元统一价;状态 4 强制 fee_status=2;收费后取消必退费
4. **撤回终态**:申请撤回后不可重投(唯一索引 + 业务校验双重保障)
5. **禁止自我成交**:投递校验 parent_user_id ≠ 当前用户
6. **处罚不连坐**:blacklist 只拦老师能力;用户封禁才全封
7. **可见性**:实际可见 = visible AND review_status=1 AND 未黑名单;敏感字段编辑 → 重审且强制隐藏
8. **评价挂人**:评价聚合按 to_user_id,不挂简历/需求
9. **敏感词**:简历/需求/评价文本提交时过滤,命中即拦截
10. **订阅消息**:43101 静默忽略;一次授权一条;站内信兜底长文本

## 6. 通知规范

- 订阅消息埋点严格按产品文档 §6.2 四点:①发布需求时 ②提交申请时 ③老师确认后 ④选中生成订单前
- 发送失败(43101)静默,不重试不报错
- 审核结果/失效/排除等长文本走**站内信**(yudao notify),**用户间禁互发**
- 红点角标:未读站内信 + 需求申请列表未读数(Redis 记录上次查看时间)

## 7. 小程序前端规范

- 登录:wx.login → code2session 后端静默注册;首次进入弹身份端选择
- 订阅授权必须**先于表单提交**:`wx.requestSubscribeMessage` 弹窗 → 允许 → 再提交
- 定位:`getFuzzyLocation` 模糊定位(个人主体申请制);拒绝授权 → 后端兜底接口(Redis 前 50 条)
- 个人页常驻:联系客服(open-type=contact)、认证状态卡、隐私政策/用户协议/注销入口
- 所有展示用后端脱敏返回值,前端**禁止自行拼接/还原任何脱敏信息**

## 8. Git 规范

- 分支:`master` 为主干;功能开发 `feature/xxx`,修复 `fix/xxx`
- 提交信息:`feat: 描述` / `fix: 描述` / `docs: 描述` / `refactor: 描述`(中文描述,动词开头)
- 设计变更:先改 docs/ 设计文档(版本号 +1)再改代码,同一提交内文档与代码同步
- 禁止提交:密钥/密码/环境变量值、target/、node_modules/、.idea 个人配置
